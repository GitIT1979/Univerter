## 1. Блокер: приложение не запускается вообще

**`Univerter-core.js:12-51` дублирует объявления `Univerter-config.js:8-41`.**

Оба файла — классические `defer`-скрипты в одной глобальной лексической области (`Univerter.html:281-283`: config → core → convert). Повторный `const PDFJS_VERSION`, `PDFJS_BASE`, `CONFIG`, `KNOWN_EXTENSIONS`, `IMAGE_EXTS`, `SHEET_EXTS`, `DOC_EXTS`, `formatRules` — это ошибка компиляции второго скрипта.

Воспроизведено тремя независимыми способами:

1. **Node, семантика браузера** (`vm.runInContext`, контрольный пример срабатывает так же):
   `Univerter-core.js: SyntaxError: Identifier 'PDFJS_VERSION' has already been declared`
2. **Настоящий браузер** — открыл `Univerter_HTML/web/Univerter.html` через `file://`:
   ```
   баннер: "⚠ Ошибка в скрипте: Uncaught SyntaxError: Identifier 'PDFJS_VERSION'
            has already been declared (Univerter-core.js, строка 1)"
   typeof isProcessing      -> undefined
   клик по режиму меняет UI -> нет
   libStatus                -> "⏳ Загрузка библиотек..."
   convertBtn.disabled      -> true
   ```
3. **Побочный эффект в следующем файле**: `Univerter-convert.js:226` падает с
   `ReferenceError: isProcessing is not defined` — и это происходит каждые 20 с (`convert.js:992-993`).

**Последствие.** Интерфейс рисуется, но не работает ничего: режимы не переключаются, файлы не добавляются, конвертация не стартует. При этом `Univerter-convert.js:996` выставляет `window.__univerterReady = true`, поэтому сторож загрузки (`Univerter.html:168`) молчит — пользователь видит только красный баннер с текстом SyntaxError. Копия в `Univerter_desktop/src/` байт-в-байт та же, десктоп сломан так же.

**Правка.** Удалить блок `Univerter-core.js:12-51` — `Univerter-config.js` уже отдаёт всё через `Object.assign(window, …)`. Затем прогнать загрузку в браузере.

**Почему это не поймали проверки.** `node --check` проверяет файл по отдельности и такие коллизии не видит по определению. Нужна проверка «загрузить все три скрипта в один контекст» — она стоит 15 строк и ловит весь класс подобных ошибок.

## 2. Высокий приоритет

### 2.1. Проверка Origin пропускает чужие домены — `Univerter_HTML/server/univerter_server.py:54-58`

```python
if not origin or origin == 'null': return True                     # 55
if origin.startswith(('http://127.0.0.1', 'http://localhost')):     # 57
```

Проверка префиксом, без границы хоста. Живой прогон на запущенном сервере:

| `Origin` | Ответ | `Access-Control-Allow-Origin` |
|---|---|---|
| `http://127.0.0.1:8765` | 200 | `http://127.0.0.1:8765` |
| `http://127.0.0.1.evil.com` | **200** | **`http://127.0.0.1.evil.com`** |
| `http://localhost.evil.com` | **200** | **`http://localhost.evil.com`** |
| `null` | **200** | **`null`** |
| `http://evil.com` | 200 / POST 403 | — |

То есть домен вида `127.0.0.1.<что угодно>` (например, через `nip.io`) или песочный iframe (`Origin: null`) получает полный доступ: может загружать документы на конвертацию и читать результат. Усилитель — заголовок `Access-Control-Allow-Private-Network: true` (`:253`), который снимает защиту Chrome от запросов к localhost с публичных страниц.

**Правка.** Разбирать origin через `urllib.parse.urlsplit`: схема `http`, хост строго в `{'127.0.0.1','localhost','[::1]'}`, любой порт; `null` разрешать только при `Sec-Fetch-Site: none/cross-site`+`file://`-сценарии, а лучше — выдавать одноразовый токен в `/health` и требовать его в `/convert` и `/ocr`. Дополнительно проверять `Host`, чтобы закрыть DNS-rebinding.

### 2.2. Адрес движка берётся из ответа самого движка — `Univerter-convert.js:237`

```js
found = Object.assign({ url }, j);   // поле url из JSON перекрывает настоящий адрес
```

`Object.assign(target, source)` перезаписывает `url`, если сервер его вернул. Плюс `/health` никак не аутентифицирован. Любой процесс, занявший порт 8765 раньше движка (или поднятый в другой папке), получает все документы и изображения страниц — при обещании «всё остаётся локально».

**Правка.** `Object.assign({}, j, { url })` + проверка, что в ответе есть `ok` и `version`.

### 2.3. Таймаут и «Остановить» не отменяют запрос

`withTimeout` (`core.js:150`) только проигрывает гонку, `rejectOnStop` (`core.js:125`) только отклоняет ожидание. `fetch` отправляется без `signal` (`core.js:1475`). Сервер сериализует OCR через `OCR_LOCK`, поэтому «осиротевший» запрос продолжает занимать движок.

**Последствие.** Медленная страница: 180 с таймаут → повтор с меньшим разрешением → ещё два круга; «Остановить» возвращает управление мгновенно, но следующая конвертация стоит в очереди за брошенным заданием. Плюс LibreOffice: `LOCK` в `univerter_server.py:47` держится до конца конвертации, даже если клиент ушёл.

**Правка.** Один `AbortController` на запрос: `abort()` в `stopConversion` и в таймауте; на сервере — таймаут на чтение тела.

### 2.4. Сервер принимает мусор за DOCX и отдаёт пустой PDF

`univerter_server.py:82` проверяет только первые два байта `PK`. Живой прогон: тело `PK-fake` → **200 OK**, PDF на 1 пустую страницу (`Producer: LibreOffice 26.8`). Пользователь получает «✓ Готово» и пустой файл вместо ошибки.

**Правка.** Проверять, что в zip есть `word/document.xml`, и что в результате есть текст (или ненулевая страница); иначе — 422 с внятным сообщением.

### 2.5. «Работает без интернета» — неправда

`Univerter.html:273-280` тянет pdf.js, JSZip, jsPDF, mammoth, Turndown, SheetJS, FileSaver с трёх CDN. Без сети не работает ни одна конвертация, а диалог «О программе» (`main.js`) утверждает обратное. Второй аспект: SRI-хэшей нет, CSP нет — компрометация CDN выполняется в контексте страницы, у которой есть доступ к выбранным пользователем файлам.

**Правка.** Либо положить библиотеки в `vendor/` (и это же снимет зависимость от сети), либо честно написать в UI «нужен интернет для загрузки библиотек» и добавить `integrity`+`crossorigin`.
